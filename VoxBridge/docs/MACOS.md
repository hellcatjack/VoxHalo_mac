# MacBook Air 独立运行

本系统基于上游 Linux VoxBridge 移植，现以 VoxHalo_mac 完整本地工作区发布。代码、模型、识别、翻译、朗读和 HLS 编码全部在本机完成；日常启动不需要连接源服务器。保留原应用的双向字幕、术语、句子修订、ESV 教会翻译提示词、独立朗读页、共享 HLS、全局 Auto 语速和登录能力。

## 首次安装

在仓库根目录运行 `./setup.sh`。完整环境要求、下载说明和卸载方式见[仓库首页](../../README.md)。脚本准备项目内 Python、固定版本模型和 llama.cpp，并将 App 安装到 `~/Applications/教会同声传译.app`。

## 启动与使用

双击“应用程序”或桌面的 **教会同声传译.app**，直接在原生控制面板完成操作。无需打开浏览器。

1. 选择 **输入来源**：系统播放声音、系统播放声音 · 只听译音、系统默认输入，或具体麦克风/声卡。
2. 选择 **朗读输出**：系统默认输出、具体扬声器/耳机，或“本机不播放 · 保留局域网朗读”。选择具体输出不会修改 macOS 的全局输出设置。
3. 选择中文→英文或英文→中文，按需填写少量 ASR 提示词。
4. 点击 **开始传译**。App 自动启动 HY-MT、Qwen ASR 和 Kokoro，再开启采集。也可以先点 **启动服务**，只加载模型。
5. 点击 **结束传译**：停止采集，处理最后一句并等待本机朗读收尾，模型保持就绪。**停止服务** 同时卸载本安装拥有的模型服务。

输入、输出、方向和提示词会保存在本机；传译期间锁定，结束后可以修改。拔出已明确选择的设备会停止传译并显示原因，不会悄悄改用其他设备。更换设备后点击 **刷新设备**。

1.3.0 起，方向选择同步核对整条语言链路：**中文 → 英文** 使用中文 ASR、原有 ESV 英译提示词、英文朗读；**英文 → 中文** 使用英文 ASR、忠实原文的中文教会术语提示词、中文朗读。两者共用分句修订、低缓冲等待、分块 PCM、本机设备选择和局域网 HLS。英文专有名词保留在中文译文中时也会朗读。切换方法：**结束传译 → 选择方向 → 开始传译**，模型服务无需重启。可在标题旁查看已安装的版本号。验证记录见 [双向翻译验证](MACOS-BIDIRECTIONAL-VERIFICATION.md)。

1.4.1 起，点击控制面板的 **字幕设置…**，可开启透明置顶、鼠标穿透的独立字幕窗。它只显示已完成的译文，不显示识别草稿或翻译生成中的文本，中英两个方向均可使用，也不依赖监控网页。

- 可调整文字颜色、已安装字体、字号（12–144 pt），以及阴影开关、颜色、浓度、模糊和距离。
- 可选择显示器、顶部／居中／底部预设，再微调水平、垂直位置和字幕宽度。垂直位置 **100%** 或 **底部居中** 可以覆盖 Dock，字幕仍保持鼠标穿透。默认白字、黑色阴影、屏幕下方居中。
- 外观设置在传译中即时生效并自动保存；菜单栏 **显示翻译字幕** 可快速开关。关闭控制面板或设置窗不会停止传译。
- **预览字幕样式** 仅在未传译时可用，明确标注为样式预览；关闭设置窗或开始传译后自动结束预览。
- 本机朗读时，字幕跟随实际输出的语音段，后续译文即使已经完成也不会抢先覆盖当前字幕。等待后续音频时保留当前字幕，整段排版且不再定时翻页；空间不足时只调整字幕字号，不改变 TTS。选择“本机不播放”时显示最新完整译文并保留自动分页。结束传译会清空字幕，字幕内容不会保存到偏好设置中。
- 字幕可使用整个屏幕，包括 Dock 区域。大字号及大阴影下，最小宽度会扩展到能容纳文字；显示器空间不足时缩小字体。拔出所选显示器后暂用主显示器，重新连接后恢复。

实现参考 [VoxHalo_mac](https://github.com/hellcatjack/VoxHalo_mac) 的原生字幕窗设计。验证记录见 [字幕功能验证](MACOS-SUBTITLE-VERIFICATION.md) 和 [字幕同步修复验证](MACOS-SUBTITLE-SYNC-VERIFICATION.md)。

- App 显示输入电平、当前原文/译文、朗读待输出时长、语速和音频连接数。
- **打开监控页** 只用于查看字幕历史及 TTS 状态；打开、刷新、关闭页面均不改变采集和传译状态。
- **听众朗读页 / 复制地址 / 二维码** 使用自动检测的局域网地址，供同一网络的手机和平板监听。听众自行点击 Start Listening 后播放，不负责启动识别。
- 本机朗读由 AVAudioEngine 直接播放分块 PCM，无需朗读网页或等待 HLS 静音切片。本机选择“不播放”时，App 仍维持共享语音流，方便局域网听众加入。局域网听众继续使用 HLS；同一句只合成一次，供两种输出共享。
- 关闭控制窗口后，传译继续运行；菜单栏的波形图标可重新打开控制面板或开始、停止服务。
- 菜单中的 **停止服务并退出**（⌘Q）停止采集、播放及后台服务后退出。退出直接释放音频，不等待整段朗读队列。
- **查看日志** 在 Finder 打开本安装的日志目录。

首次访问桌面项目、麦克风或系统声音时，按 macOS 提示授权。系统声音权限位于“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”；麦克风权限位于“麦克风”。权限属于 **教会同声传译**，不再由 Chrome 负责。不需要完全磁盘访问权限。拒绝授权会在控制面板显示错误；更改权限后可能需要重启 App。

“系统播放声音”使用 ScreenCaptureKit；1.5.0 新增的 **“系统播放声音 · 只听译音”** 使用 macOS 14.2+ 的 Core Audio tap，采集时抑制原声输出，停止采集后恢复。两者均排除本 App 的朗读，避免自身译音回流。其他应用播放的声音仍会被采集，包括同机浏览器朗读页；本机直接使用原生朗读即可。麦克风可能从空气中收录扬声器译音，使用麦克风时建议将朗读输出到耳机。

油管测试选择 **系统播放声音 · 只听译音 → 系统默认输出 → 英文 → 中文**，先开始传译，再播放浏览器视频。视频音量保持开启；App 负责抑制原声，不要将网页静音。结束测试时先暂停视频，再结束传译。无需虚拟声卡。设置及实测记录见 [油管译音测试环境](MACOS-YOUTUBE-TEST.md)。

App 是原生控制台，不需要终端，也不连接远端服务器；它复用已安装的模型与运行环境，不把数 GB 模型重复复制进 App。请保留安装时的整个 `VoxHalo_mac` 仓库目录。仅复制 `.app` 到另一台未安装模型的 Mac，不构成完整迁移。

仓库根目录的 `./macos.sh start` 和 `./macos.sh stop` 可管理模型服务；采集与本机播放通过 App 操作。

- 只读监控：`http://127.0.0.1:8024`
- 独立听众：App 显示的局域网地址或二维码。

```bash
cd VoxHalo_mac/VoxBridge
./macos.sh start
./macos.sh status
./macos.sh check
./macos.sh stop
```

一键脚本不设置开机自启。关闭监控网页不影响采集、翻译或朗读；停止脚本会关闭本进程的 HLS / FFmpeg 和翻译服务。启动、停止有独占锁，PID 与完整命令行一致才会发停止信号。端口被其他程序占用时明确报错，不终止其他程序。

App 的源码位于 `deploy/macos/app/`，使用系统 Swift / AppKit，不依赖 Electron。
在装有 Xcode 或相应命令行工具的本机重新构建、安装：

```bash
../.venv/bin/python tools/build_macos_app.py --desktop-link
```

默认安装到 `/Applications/教会同声传译.app`，桌面放置一个指向它的入口；可以通过
`--destination "$HOME/Applications/教会同声传译.app"` 改为用户级安装。
重建前先退出 App。安装器校验已有应用标识，不覆盖其他应用或桌面同名文件。
本机构建使用临时签名，未做 Developer ID 签名或 Apple 公证；这不是用于任意 Mac 分发的安装包。

本仓库只提供当前完整系统，未包含早期 Zipformer 网页原型。旧 VoxHalo 字幕客户端保存在 Git 历史和 `backup/pre-local-system-2026-09-14` 分支。

## 沿用本机已验证的模型设置

| 部分 | 本机设置 |
|---|---|
| ASR | Qwen3-ASR 0.6B；MLX0.32.2、mlx-qwen3-asr0.4.0；Metal GPU |
| 精度 | affine INT8 group64 权重；激活及未量化层 FP16 |
| 流式方式 | 有界窗口重复识别，约2秒触发一次；接入 VoxBridge 原分段与 revision 协议，非原生缓存增量流式 |
| 默认音频边界 | 12秒分段阈值，0.8秒静音候选，0.32秒重叠；保留原系统的未完句保护与最终复核 |
| 翻译 | HY-MT1.5-1.8B Q8_0，llama.cpp b10809，Metal GPU layers99、flash attention、ctx4096、parallel1、threads2、cache-ram0 |
| 翻译生成 | temperature0、top_p0.6、top_k20、repeat_penalty1.05、repeat_last_n64、max_tokens256、cache_prompt=false；保留源系统超长输出重试及教会提示词 |
| 调度 | ASR 固定在一个 MLX 线程；ASR 与 HY-MT 请求共享 GPU 互斥锁；音频接收独立继续 |
| VAD | 本机已存在的 Silero ONNX，由单线程 CPU / NumPy 直接运行，无需 PyTorch |
| TTS | 源项目 Kokoro English v1.0 / Chinese v1.1 ONNX；am_michael / zm_029（中文男声）、基础 speed1.05、CPU2线程 |
| 朗读稳定门 | 已确认原文默认稳定3秒；本机实际待播≤2秒且反馈新鲜时缩短为1秒；未确认最新句仍等封口，保留最终复核、最新句4秒保护与全局 Auto速度 |
| 分块朗读 | 完整译文按自然语句边界拆成较短音频；首块生成后即可发布，后续块连续播放；仅最后一块附加原有300ms句末停顿 |

1.4.2 修复中文语速被取整的问题。Mac 使用独立的 `kokoro-v1.1-zh-float-speed.onnx`，仅把原模型的 speed 输入声明改为浮点数，权重和中文男声不变；调用层保留小数。基础 1.05 和 Auto 追赶档现均实际生效，英文路径及句间停顿保持原样。见 [中文语速修复验证](MACOS-CHINESE-TTS-SPEED-VERIFICATION.md)。

1.4.3 修复中文句中频繁断开：中文优先按完整句末分段，普通长句不再因为逗号被拆成多次独立合成。超过约 120 字的句子才寻找靠后的分句边界，无标点时优先保留词语、经文编号和时间；句末标点与闭引号随正文保留。数字展开等极端输入另按 Kokoro 音素容量分批，防止截断漏读。继续使用原中文男声、小数语速和 Auto 追赶；英文切分、播放调度和字幕时钟保持原样。整句合成会增加长句首音等待，换取更连贯的句中语气。见 [中文切分验证](MACOS-CHINESE-TTS-SEGMENTATION-VERIFICATION.md)。

部署进程不加载 CUDA、ROCm、vLLM、PyTorch 或 Apple Neural Engine。Kokoro 使用 CPU，让 Metal 优先服务识别与翻译。保留源项目 Linux 后端的代码和配置，Mac 启动脚本明确选择 `--backend mlx`。

原生 PCM 使用回环地址及控制凭据访问。App 根据实际已渲染采样数报告待播时长，反馈超过2秒自动失效并恢复普通稳定窗口。音频游标校验会话、句子版本、块序和完整句尾；断连、缺块或停止后的旧回调不能被当成完整播放。服务器保留的 PCM 与预合成缓存分别有16MiB/256块上限。

精确上下文预翻译已实现为可选实验项，默认关闭。只有多次真实 ASR 解码一致且形成完整边界的候选才可预计算；正式提交必须与原文、方向、提示词、模型参数及会话完全匹配才能复用。诊断时可用 `VOXBRIDGE_SPECULATIVE_TRANSLATION=1 ./macos.sh start` 显式启用，需先停止既有服务。实际取舍与长测数据见 [低延迟开发验证](MACOS-LOW-LATENCY-VERIFICATION.md)。

## 独立本地资源与重装

Python 固定在工作区 `./.venv/bin/python`，即 VoxBridge 内的 `../.venv/bin/python`。不使用系统 Python，也不复制 Linux 虚拟环境。

资源均在同一工作区内：

- `models/qwen3-asr-0.6b/`：已验证的官方 ASR 权重（安装器固定提交和 SHA-256）。
- `models/translation-experiments/gguf/HY-MT1.5-1.8B-Q8_0.gguf`：已验证的翻译权重。
- `runtime/translation-llama/llama-b10809/`：固定版本 Metal 翻译运行时及 dylib。
- `models/vad/silero_vad.onnx`：已验证的 VAD 权重。
- `models/kokoro/`：安装器下载并核对5个中英模型/音色/词表文件，再在隔离工具环境自动生成已验证的中文浮点语速模型。原始模型保留。来源与校验策略见[模型说明](../../docs/MODELS.md)。
- `.venv` 内固定版本的 imageio-ffmpeg 与 espeakng-loader 提供 Apple Silicon FFmpeg 和发音资源；hls.js 随源码本地提供。

移动到别的位置时应搬迁整个 `VoxHalo_mac` 工作区，并重建虚拟环境；不要单独复制 VoxBridge 子目录后假定模型仍在。源码和模型不依赖远端挂载或网络文件系统。

在本地模型已准备好的情况下重建依赖：

```bash
cd VoxHalo_mac/VoxBridge
./deploy/macos/setup-runtime.sh
```

`deploy/macos/requirements.lock` 记录本次验证的完整包版本；安装依赖需要网络或预先保存的 wheel 缓存，正常推理无需网络。启动设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，缺少资源应报错，不使用远端或云端备用模型。

## 本机与局域网监听

Mac 启动脚本默认监听 `0.0.0.0:8024`，并使用 `--public-listener-url auto`。二维码和朗读链接每次加载主页面时都会重新检测本机局域网 IPv4：优先默认路由上的 Wi-Fi / 以太网接口，跳过回环、VPN 隧道、未启用接口和自分配地址。没有互联网默认路由时，仍可从已连接的物理局域网接口获得地址。

听众入口为 `http://<Mac 的局域网 IP>:8024/listen`，以 App 实际显示的地址和二维码为准。换网或 DHCP 地址变化后，App 的状态查询会更新地址和二维码；监控页刷新后同步更新。未检测到局域网时显示提示，不生成回环地址二维码，本机采集和朗读仍可使用。

同一局域网的手机直接扫描二维码进入朗读页。Mac 操作员通过 App 采集；监控页可以在本机或局域网浏览器访问，均不控制业务。HY-MT 内部服务仍仅监听回环端口8876。

如需要固定的 HTTPS 地址，可显式设置 `VOXBRIDGE_LISTENER_URL`；如需覆盖监听接口，可设置 `VOXBRIDGE_HOST`。这些选项按部署需要使用，默认无需手工填写 IP。本配置不会建立公网转发。

## 日志和验收

- `logs/macos-app.log`、`logs/macos-translation.log`：启动与运行日志。
- `artifacts/macos-service/`：本机 PID 记录、管理锁及权限 0600 的原生生产者控制凭据。原生模式的识别 WebSocket 只接受回环地址和该凭据；不要把凭据放进网页或 URL。
- `artifacts/macos/`：本地测试时的音频、事件及输出，不随仓库发布；普通使用不会保存录音。
- `tools/macos_e2e.py`：按100ms真实节奏输入本地PCM16 WAV，验证ASR→翻译→Kokoro→AAC/HLS、双听众共享与退出清理；静默运行，不播放音频。
- `docs/MACOS-VERIFICATION.md`：完整链路、新视频网页测试及已知错词。
- `docs/macos-mlx-report.md`、`docs/macos-listener-report.md`：适配模块的测试证据。

跨设备共享保证相同的语音内容和源句顺序，不保证手机与电脑扬声器逐采样同步。iPhone 锁屏表现仍需要真机验收；本次本地 Mac 测试不能替代它。ASR 与译文仍可能存在错词或语义偏差，功能移植完成不代表识别准确率提高。
