# Qwen 本地长句优化：实施与验收记录

本文件是实验记录，不是性能承诺。所有推理和验证均在本地 AMD 主机进行，没有使用云端识别、翻译或朗读服务。

## 回退与范围

- 修改前的 annotated tag：`pre-qwen-long-speech-20260912`，指向 `2cd2606d07ac8afc322e098fd29d01391576fa2d`；本阶段验收时尚未推送，后续主线发布见[归档说明](../releases/2026-09-12-main-handoff.md)。
- 代码和用户级服务配置已私下备份。备份目录权限为 0700。
- `b899fa2` 是 Qwen-only 恢复点。回退长句策略时应保留这个版本之后的 Zipformer 禁用，不能直接恢复旧 tag 而重新启用 XL。
- Web 仍是 8024；HY 使用同一 AMD 主机原有的 8001 接口。所有 Python 使用项目原有 venv，没有修改 ROCm、Torch、vLLM、NumPy 或 TTS 依赖。
- 英文→中文、HY 提示词、声音、Auto 与 HLS 播放逻辑不变。

## 已实现的独立模块

1. UI 固定显示 Qwen3-ASR，旧的 XL 浏览器偏好迁回 Qwen，其他偏好不变。麦克风、媒体共享和调试 PCM 都请求 Qwen。
2. WebSocket 在调用注册表之前拒绝 XL；注册表也不能导入、构造或缓存 XL。保留源码、磁盘模型和独立 adapter 测试。
3. `DecodeObservation` 区分 API 调用、真实 `chunk_id` 推进和实际观察到的假设。一次调用完成多个解码块，也只有一次可观察的最终假设。
4. `PendingTextClock` 有界跟踪未提交文字的首次出现时间。增长不重置前缀年龄，提交后剩余文字保留各自年龄；整段替换重建年龄。
5. 可选的较小子句候选仅用于中文→英文，只在已有标点处选择边界。保留实际解码一致性、回滚窗口、跨段继承以及原有 TTS 确认路径。没有标点时不按字数强切。
6. 生产 CLI `--qwen-submission-mode off|shadow`，默认 `off`；服务可通过 `VOXBRIDGE_QWEN_SUBMISSION_MODE` 设置。`shadow` 只记录诊断，不改变提交决定。显式 CLI 参数优先于环境变量。未通过质量门槛的 `adaptive` 被生产 CLI/环境配置拒绝，仅保留在隔离 benchmark 工具内研究。

## 验证与发现

### 基线与自动化

原有 2 个 README 安装说明检查失败，经授权修正后，干净基线为 666 passed。

- Qwen-only 协议、浏览器和采集验证：36 passed。
- 独立 native adapter、registry、probe、文档检查：32 passed。
- 初次策略集成的字幕/翻译/朗读协议及单元测试：167 passed。
- 开发中完整回归：685 passed / 179.96 秒。此数字是当时快照；新增验收用例后的最终结果另记。
- 最终完整回归：691 passed / 175.62 秒；随后文档检查再次 14 passed。
- Chromium 桌面和手机宽度截图已检查，无页面错误或横向溢出。AMD 未安装 agent-browser，使用已有 Playwright。WebKit 自动化不冒充真实 iPhone 验证。

### 三种时间不能混用

| 指标 | 含义 | 限制 |
| --- | --- | --- |
| 完整识别单元到提交等待 | 同一 segment 中，该完整文字首次出现在 partial 后多久提交 | 标点或字词变更可能无法精确匹配，必须报告样本数 |
| 最老已识别待提交文字年龄 | 未提交前缀最早被观察到后经过多久 | 从导出的 partial 重建时，跨窗口会保守重置，不等于音源延迟 |
| 相邻字幕间隔 | 两次提交事件之间多久 | 包含真实讲话停顿和句子长短，不能称为识别延迟 |

没有可靠的源音频末词对齐真值，因此 `source_to_commit_latency_sec` 明确为 null，不编造端到端延迟或 CER。

### 第一轮真实原音对照：未通过，不上线

使用 2026-09-06 原始视频导出的 16 kHz WAV 前 180 秒，以 1× 输入。使用本机 HY，测试 app 不监听新端口、不连接公开 listener、不启动 TTS 分发。

| 45 秒窗口 | 原策略 | 24 字目标 / 8 秒预算 |
| --- | ---: | ---: |
| 真实解码块 | 298 | 298 |
| 提交单元 | 27 | 31 |
| 完整单元等待 P50 | 1.897 秒 | 1.797 秒 |
| 完整单元等待 P95 | 3.009 秒 | 3.037 秒 |
| 精确匹配计时样本 | 22 | 27 |
| 字幕间隔 P95（非识别延迟） | 10.942 秒 | 10.916 秒 |

发现新增漏句和重复：“乐高积木……”一段丢失，“对不对”和“那其中有一个……”重复。这组参数不满足质量门槛，也不能声称 P95 改善。

追踪到一类原因：Qwen 撤回已提交单元位置的逗号后，旧的处理游标和新的分句数量不一致，使下一句被误判为已处理。已添加真实例子的回归测试；对已经处理的前缀允许标点修订对齐，但待提交内容的边界一致性仍严格判断，数字旁标点和小数点不被忽略。复验消除了这处漏句，但没有消除所有跨段问题。

### 受限网络下独立复验：仍未通过质量门槛

同一原始 WAV、1×、180 秒，Qwen 缓存模型冷加载，HY 仍使用同机原有服务；测试进程及子进程只能访问 localhost 和服务器自身地址。

| 指标 | 原策略 | 修订后的候选策略 |
| --- | ---: | ---: |
| 提交单元 | 27 | 33 |
| 完整单元等待 P95 | 2.999 秒（21 个样本） | 3.397 秒（29 个样本） |
| 最老已识别待提交文字年龄 P95 | 12.552 秒（24 个样本） | 16.871 秒（32 个样本） |
| 相邻字幕间隔 P95 | 10.843 秒 | 9.153 秒 |
| 完整提交原文长度（含标点） | 725 | 742 |
| HY 连接/调用异常 | 0 | 0 |

“乐高积木”漏句消除，但候选策略仍额外重复“那其中有一个又帅又很有个性的尼克狐”。更短的字幕间隔掩盖了实际文字等待没有改善。因此不启用候选策略，不以字幕更多宣称延迟降低。完整单元计时与重建前缀年龄的匹配覆盖不同，不进行未匹配单元的假设填补。

两组 HY 都能输出英文。对照中也观察到既有 HY 数字误译和末尾未完整输入造成的目标语言校验拒绝，不能据此声称翻译整体无误；没有为通过对照修改提示词。待提交原文已经出现新增重复，故无需用主观译文流畅度替代源文本质量门槛。

结论：本轮生产仅部署 Qwen-only 和 shadow 诊断。24/8 候选保留为隔离研究，不上线。30/20 秒窗口实验按先决质量门槛停止，维持 45 秒。进一步修改必须先解决基于句子序号的跨段修订与动态分句之间的一致性问题，不能再叠加更激进的时间参数。

首轮同时有部分 CPU 自动化回归运行，且第一组包含冷启动首次解码。因此首轮 CPU/GPU 耗时不用于证明加速。原始数据保留；早期结果汇总仅取 `final.text` 的问题已修正，当前汇总使用完整 `final.committed_text`，并从原始事件重算时间。

## 可选标点组件：兼容性门槛未通过

核对官方 `funasr-onnx 0.4.3` 的包声明，其要求 NumPy ≤1.26.4；当前环境是 NumPy 2.2.6、ONNX Runtime 1.28.0。根据不更换现有推理依赖栈的约束，本轮不安装、不降级、不增加 CT-Transformer 运行资源。[官方包元数据](https://pypi.org/pypi/funasr-onnx/json)、[官方安装声明](https://github.com/modelscope/FunASR/blob/main/runtime/python/onnxruntime/setup.py)。

同时确认官方 wrapper 在模型目录不存在时会下载、ONNX 缺失时会尝试导出；不能把默认示例直接接进受“禁止运行时联网”约束的生产链路。以后如重新评估，仍需完整离线包和 revision-aware 边界适配。[官方加载代码](https://github.com/modelscope/FunASR/blob/main/runtime/python/onnxruntime/funasr_onnx/punc_bin.py)。

## 离线验证

未更改整机网络或影响 SSH。使用单独的 systemd 测试单元，将测试进程及子进程限制为本机通信。

- 外部地址对照：普通进程访问 1.1.1.1 返回 HTTP 301；受限进程不能连接。原有 HY health 仍可访问。
- 只放行 localhost 的初次 ASR/HY 测试误拦截了同机的局域网地址，出现 HY 超时。已停止这一个隔离测试单元，保留失败数据，不纳入性能结果；重新放行服务器自身地址后 HY health 正常。
- 中英文 TTS 在受限进程内首次加载并生成 WAV 成功：英文 2.283 秒音频、中文 2.731 秒音频。包括冷加载的调用耗时分别 0.997 秒、2.754 秒；不将其当成稳定运行吞吐量。
- ASR/HY 的修正隔离对照两组均完成，HY 调用异常为 0。隔离测试退出后出现 vLLM 子进程关闭告警，发生在收到最终事件之后；不是生产服务故障，不计作推理期间失败。
- 第二份原始讲道 WAV 的 90 秒 shadow 冒烟完成：150 次真实解码、13 个提交单元、341 字完整原文、15 条英文翻译事件（含修订），HY 调用异常 0；693 条诊断记录中 `adaptive_applied` 全部为 false。这是离线功能验证，不是原文准确率或性能优越性的证明。
- 最后完成生产重启，具体检查见下节。
