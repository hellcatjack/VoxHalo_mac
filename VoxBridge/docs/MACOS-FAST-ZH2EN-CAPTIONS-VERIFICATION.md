# 快速中文→英文字幕验证（build 44）

本轮只调整英文阅读字幕，不更换模型，不修改识别与翻译提示词、语音固化、TTS 合成或播放调度。中文、日文及其余五种目标语言保留各自原有计时和分页。英文参数对所有译成英文的方向生效。

## 修复内容

- 英文计时改为 `max(3.5, 0.2 + 阅读词数 / 4.8)` 秒，固定约 288 词/分钟；每屏最低 **3.5 秒**，最多约 36 词，并服从实际固定字号与窗口容量。混合汉字继续消耗相应阅读量。
- 完整词边界避免原分页在第 36 个词开头回退到第 35 词；长句均衡分页，减少只有几词的尾页所增加的最低停留成本。
- 英文队列比较“均衡后按实际字体分页”和“先按实际字体分页再限制词量”两种确定方案，检查字词守恒、非空、字号容量和词数限制，再选择总阅读预算更低者，防止大字号让均衡页再次裂成更多短页。
- 页形只取决于文本、固定策略及字体容量，不随 TTS 速度或队列积压改变。相同完整译文在手动字号重排后仍保留实际已读页和未读游标，不因重新计算的页形不同而重播。
- 新来源版本尚待翻译时，手动改字号也会重排保留的旧版完整译文及实际未读游标，避免相同译文恢复后沿用旧容量页面，造成队列卡住。旧可见页仍获得完整阅读时间。
- 当前屏幕文字、字号与完整阅读期限保持冻结。未读内容继续按顺序保留，不能通过删句、截尾或缩短已显示时间追赶朗读。

这些是工程阅读预算，不是每位母语读者都能按此速度读完的保证。大字号或持续输入超过阅读吞吐时，仍会保留未读内容排队。

## 验证方法

历史输入为 600 秒中文语音、112 个独立来源版本、2386 个英文阅读词。历史材料缺少准确翻译完成时间，因此以各句第一次 PCM 被本机接受的时间作为保守的译文可用性上界；回放等待时间不能称为模型翻译延迟或实际屏幕绘制延迟。回放编译真实生产 NativeSession、ReadingSubtitleQueue 与 CoreText，使用 50 毫秒虚拟时钟，不启动模型、设备或实际字幕窗口。

现场复测使用用户当前 Chrome 视频和 App 的系统播放音频采集、只听译音、系统输出及阅读优先设置。App AX 与监控 GET 采样用于观察显示队列和来源关系；它们不提供实际耳边发声或物理绘制时刻。现场未匹配的长句、修订或分页，不能直接认定为漏句；完整内容由真实队列守恒回归单独验证。

## 当前 Chrome 快速中文片段

初次现场采集连续播放 601.038 秒，视频位置为 140.176–741.214 秒，原速 1 倍、系统播放输入、只听译音、系统默认输出，40 pt 固定字号、约 90% 宽度。第一候选的 252 词/分钟仍在中段积压：被动监控与 App AX 采样的匹配首屏等待中位约 25.8 秒。字幕领先于朗读，不能单独证明接近最新译文。

由这份完整被动监控重建的输入有 110 个完成版本、103 个成功翻译来源、7 次第二版修订。成功来源最新译文合计 2376 阅读词；部分连续 60 秒窗口达到 294、268、278 词，超过第一候选吞吐。动态拼接下一页只能改善首前缀出现时间，整句阅读完成的中位成本没有下降，因此最终没有引入这种更复杂的队列切页。

最终生产源码在同一输入上回放：最新译文首屏等待中位 **7.042 秒 / P95 17.506 秒**，末页开始中位 **7.513 秒**，整句完整阅读预算结束中位 **13.411 秒**。Git HEAD 的 build 43 原生产代码在相同输入上的首屏为 **86.286 / P95 152.399 秒**，末页中位 87.280 秒、阅读结束中位 96.064 秒，排空 764.300 秒；本轮第一候选首屏约 26.471 秒、阅读结束约 33.430 秒。最终 100 屏、114 页、最短 3.5 秒、最长 7.7 秒，最后阅读期限及排空为 612.200 秒。新旧均保留独立的失译条目；103 个成功来源的最新完整译文逐来源、逐版本非空白字符全部相等。已显示旧修订的内容另行保留统计，不能误算为重复字幕。

监控没有提供真实 MT 完成时刻、source ledger epoch 或全部 reset 事件。此回放使用各版本第一次完整 GET 响应完成时刻作为可用性代理，不借用未来修订译文填充旧版，也不把 native 音频 epoch 当作来源 epoch。P95 使用线性分位数；这些值表示重建队列的排队成本，不是模型、物理显示或耳边发声延迟。现场 AX 采样也有间隔，不能宣称连续帧验收。

**独立失译边界：**这轮有一条原句在常规与严格目标语言重试后均返回中文，被目标语言检查拒绝，没有完整英文译文。使用现有短恢复模板的本地复现仍返回中文；请求成功且没有拒答措辞。该条在回放中仍标为未译，不能声称整段模型翻译零漏句，也不能用中文冒充英文发布。本次没有更改提示词、重试流程或模型来掩盖这条失败。

## 最终版本现场长测

固定证书安装最终 build 44 后，以相同视频、原速和设备设置再次连续播放 **627.814 秒（10 分 28 秒）**：140.717–768.531 秒，随后暂停视频并正常结束传译，最后一句英文字幕保留，服务回到就绪。确认实际保存设置为阅读优先、字幕开启、40 pt、约 90% 宽度；安装后 binary 与最终编译产物相同，服务源码与 canonical 源码相同，三个采集／语音核心保护文件的校验值保持不变。

最终采集含 1498 次被动监控 GET。只使用 AX 调用完成前已返回的 GET，不使用未来版本补配，且明确区分合法冻结的旧完整译文与最新版本首显。在实际输入窗口内，新完整 MT 第一次 GET 响应到首个 AX 字幕页的 **91 个匹配样本，中位 2.166 秒 / P95 7.157 秒 / 最大 10.627 秒**。匹配字幕与当时新鲜 `playing` PCM 来源比较的 378 帧中：328 帧领先、37 帧同源、13 帧不确定，未观测到落后。这里的 `playing` 是客户端反馈，不是耳边声音时间；AX 也不是屏幕像素绘制时刻。

输入窗口 412 个业务 AX 样本中 396 个可严格提取和匹配；原始 AX 最大采样空档为 40.005 秒。51 个有界显示区间里，26 个首末样本端点间隔至少 3.5 秒，25 个因边界不确定而无法证明实际长度，没有观察到上界小于下限的区间；另有删失区间。因此现场采样不能证明每一物理帧的停留时间，3.5 秒下限由真实生产队列回归与回放验证。

两轮起点相差约 0.54 秒，实际 ASR 分句和修订数也不同；上述现场改善是辅助证据，严格代码因果比较使用前节相同冻结输入。最终现场 118 个源句、124 个来源版本，123 个成功 MT 版本；117 个源句成功翻译。同一条独立失译在最终测试中再次出现（本轮来源 103），不能称为已恢复。无监控 HTTP 错误，字幕改善也不能等同于模型准确性或翻译零遗漏。

最终现场记录再用真实生产队列／CoreText 回放，**117 个最新成功译文的完整字符审计全部通过**：116 个按各自最新版本的显示页逐字守恒；另 1 个新版本只改来源末尾标点，完整译文与此前已显示版本逐字节相同，因此继承那一整句的显示覆盖，不再次重播。最新成功译文合计 2451 阅读词，112 屏、最短 3.5 秒、最长 7.7 秒，换页均等待前屏完整预算；零音频输入也能排空。失败来源仍独立标为未译。最终现场 fixture、同文继承证据和逐句审计保存在 `final-live-replay`，不把采样漏配当字幕丢字，也不把已译文本守恒当原文语义准确性保证。
