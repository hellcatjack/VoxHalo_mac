# 独立阅读字幕验证

本轮将“阅读优先”接到已完成译文和独立的阅读时钟。默认有声输出也使用该通道，不再等待源句获准朗读、PCM 发布或声卡前进。“跟随朗读”继续使用原有音频进度。字幕的显示、隐藏、模式和字体调整不控制音频调度。

验证分为生产接线回归、历史事件回放及人工压力场景。历史回放采用冻结后的 `NativeSession`、`ReadingSubtitleQueue` 和真实 CoreText 字体布局，使用虚拟 50 毫秒时钟加速执行。它没有启动模型、业务服务、音频设备或屏幕字幕窗口，不能当作新版 YouTube 现场测试、物理屏幕绘制或耳边音频测量。

## 阅读规则

- 中文、日文保留独立的文字量计时，最低 3 秒；阅读速率固定为原基础值，密集长屏继续获得额外时间，不随 TTS 或积压自动加速。
- 英文、法文、西班牙文、意大利文、葡萄牙文、印地文分别保留 3.5 词/秒、最低 3.5 秒及 0.5 秒定位时间。
- 中文、日文每屏最多 10 个阅读工作单位，相当于 60 个汉字；实际字号及显示区域可能要求更小的页面。拉丁词语和数字也消耗阅读量。
- 已经显示的整屏文字、布局和阅读截止时间保持不变。下一译文在预算到期后立即进入下一屏；邻接的已完成短句在换屏时合并，分担同一次最低停留时间。
- 固定字号只接受用户的手动修改，不因内容变长自动缩小。展示不主动插入换行字符；固定宽度内的自然排版和分页仍可能出现。
- 未读内容保留顺序；不能通过丢句、跳过长句或缩短已经公布的阅读时间制造实时性。

这些是工程阅读预算，不构成所有母语读者都能读完的保证。持续输入超过阅读吞吐时，保留全部内容、固定字体和最低时长必然产生排队。

## 英文→中文：准确翻译完成时刻

主输入来自 build 42 前轮记录的同一 CNBC 视频。实际连续视频内容为 **634 秒**；加上启动和结束阶段，事件时间线为 **651.967 秒**。trace 提供提交、翻译完成的时间、revision 和文本 hash，监控快照提供相同版本的实际文本及源 token IDs。所有普通译文均校验 hash，没有用最终译文替换未观察到的旧 revision。

这份回放没有完全未出现的最新、非退休源版本。36 号场景中，两个旧 revision 由相应新 revision 展示，另一个子行被父行吸收；其三个原 token 在父行范围中连续存在。该结果验证展示覆盖，不证明原音频的识别或翻译逐字正确。

一项只用于恢复朗读增量的 audio-only addition 没有发出普通 `sentence_translation`，故不作为额外字幕译文事件重放。其内容已由父行 48 的 revision 2 普通整句译文在 trace 时钟 **269.050 秒**完整覆盖；补句翻译在 **270.704 秒**才完成，再注入一次会重复。这项排除不表示遗漏已经朗读的内容。

36 号场景有 22 个首屏晚于**历史共享 PCM 发布**。共享首包发布不是本机实际开始发声，因此这里不能宣称每张字幕都领先实际朗读，也不能仅凭这些事件认定屏幕晚于耳边声音。后续长句页面的等待是分页阅读成本，不能与首次译文展示延迟混为一谈。

## 中文→英文：历史可用性上界

另一份历史报告包含 600 秒中文音频、213 个已接受 PCM 块和 112 个完整来源。每句只取第一块的全文一次，全部与相同 revision 的阅读记录匹配。112 个来源各重放一个版本：107 个 revision 1、5 个 revision 2；没有同一来源的两个 revision，也没有不同来源的相同整句英文污染统计。

这份报告没有准确的翻译完成时刻。测试仅在原第一块 PCM 被本机接受时让其完整译文进入队列，作为保守的可用性上界。输出中的翻译完成延迟字段设为 `null`，不能据此推导模型延迟或展示改善。

生产 `SubtitleReading.work` 直接计算这份译文为 **2386 词**：相对 600 秒原语音为 **238.6 词/分钟**；相对首句至末句的 632.753 秒可用性时间线为 **226.25 词/分钟**。当前阅读速率为 210 词/分钟，另有定位和最低停留时间，吞吐不足会积压。大字体增加页面及每页最低时间，积压更明显。

这是需要保留的边界，不能声称中文扩展为长英文时已经达到实时性目标。若后续继续优化，应分别验证英文母语阅读预算和分页成本，不以 TTS 加速或遗漏未读内容掩盖排队。

## 人工压力与生产接线

以下是人工构造输入，不能称为视频实测：

- 超长中文一句：12 屏，94.2 秒虚拟排空，每屏约 7.82 秒；逐字守恒，没有遗漏、重复、调序或主动换行。
- 同一时刻完成的 60 个短句：11 屏显示全部 60 个来源，86.2 秒虚拟排空；每屏至少 3 秒，逐字守恒。瞬间超过可读吞吐时保留内容排队。

生产接线短测试编译真实 App 源码并验证：默认有声输出设置下，翻译完成事件返回时字幕即可显示；声卡始终为零时仍能换页；语音反馈不改变阅读期限；隐藏和切换模式补回未获得的阅读时间；36/72 号字体重配不会创建采集或 PCM 调度。该短测试没有启动设备，实际播放中的样本独立性仍需单独用音频回放和 PCM hash 检验。

相关验证入口：

- `tests/test_native_independent_reading.py`：实际 `NativeSession` 接线及零 PCM 回归。
- `tests/test_reading_subtitles.py`：阅读预算、顺序、修订、重复、封口和未读内容守恒。
- `tests/macos/prepare_native_caption_replay.py`：根据 trace 和监控快照重建版本；无法匹配时失败，不替换旧译文。
- `tests/macos/NativeIndependentCaptionReplay.swift`：真实队列及 CoreText 几何的离线虚拟时钟回放。

六项回放均通过。原始输入、输出、源文件 hash 和日志保留于本地验收产物，不纳入 Git，也不把上述虚拟时钟指标当作新版现场端到端延迟。

## build 43：当前 Chrome 视频现场验收

本机安装并运行 **LingoCove 1.0.0（build 43）**，复用固定签名证书；本次更新和启动没有新增目录或系统音频授权弹窗。全套检查完成：**1491 通过、33 跳过，耗时 420.10 秒**。本轮没有更换模型或修改 TTS 播放通道。

现场使用当前 Chrome 的 CNBC 视频，以 1 倍速连续播放 **25.453648–649.988320 秒**，实际内容 **624.534672 秒（10 分 24.5 秒）**。方向为英文→中文，保持系统播放音频采集、当前音频输出设置、40 号固定字体、90% 宽度和阅读优先模式。结束时视频已暂停，App 正常结束传译并排空；最终会话为 `stopped`、错误为空，原生 `pending` 和 `playback` 均为空，业务服务保持就绪。

阅读与朗读的比较针对 583 个同时有“正在朗读”文本的 AX 样本，匹配完整译文、朗读文本及来源顺序后判断。356 个样本中阅读字幕已经显示后续来源，而朗读仍在前面的来源；这提供了阅读显示与朗读进度分离的现场证据。38 个样本同源或同屏含相邻来源，189 个样本因分页、朗读片段或无法唯一匹配而保留未知。这里不能据此宣称每条字幕都领先耳边音频，帧数也不是句数。

时延数字是 **82 个可匹配版本的采样观测差**，不是全部译文的延迟，也不是模型真正完成翻译到屏幕绘制的耗时。GET 与 AX 独立采样，因此有 −0.407 秒的负值。AX 采集在视频播放约 20.2 秒后才开始，期间另有 9 个 18.653–48.190 秒的采样空档，合计 279.606 秒；部分最大观测差包含等待下一次采样的时间。没有用这些空档推断字幕停留、改写或漏句。

可读性检查为相邻不同屏样本构造停留时间上下界，遇到采样空档或首尾则标为不可判断。在可限定的段中没有发现上界短于 3 秒的情况；38 段在相同 AX 文字样本间覆盖至少 3 秒。该结果支持最低阅读预算回归，仍不是连续像素绘制或每位读者读完的测量。

监控快照保存了完整译文、revision 和源 token 范围；现场 AX 不提供句子与页面身份，长句也会分页。因此，55 个未匹配独特前缀的版本不能直接认定为漏句，现场采样也不能证明逐句完整屏幕覆盖。未读内容和修订覆盖由前述真实队列守恒测试及历史来源范围回放单独验证。本轮没有进行逐字 ASR 准确率评判，也没有测量耳边实际发声时刻。
