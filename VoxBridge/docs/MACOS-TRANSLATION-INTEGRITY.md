# 双向翻译完整性优化 · App 1.5.1（build 16）

本次基于 1.5.0 的双向长时间评估，优先处理异常译文、晚到内容与分句完整性。

## 行为变化

- HY-MT 返回翻译规则说明或极端异常的长度扩张时，使用简短翻译模板重试一次。仍异常或扩大生成预算后依然未完成时记录失败，不把说明或残缺译文送入 TTS。正常请求保留已验证的采样配置。
- 已发布语音对应的原文版本固定保存。后续修订若只在末尾增加内容，将新增部分单独翻译并进入现有顺序朗读队列；已有后续条目覆盖的内容不再补读。如果下一条在补读后才到达，只省去其与补读完全对齐的开头，继续翻译朗读剩余内容；整条已覆盖时跳过并继续后续队列。标点修改与改写不触发整句重播。
- 明显未完成的英文介词短语、限定词或孤立主语保留到后文；相邻关系从句尽量与前文组合。中文较短的条件句尽量保留条件与结论，避免软标点将其拆开。完整短句保持原有放行路径，尾句仍使用现有有界等待和停止收尾。
- 根据当前原文实际出现的词匹配有限圣经专名表，双向统一常见人物、地点和称谓；术语按原文出现顺序列出，搭配 HY-MT 官方简短模板。无术语匹配时保持原有教会提示词；异常重试去掉术语提示，避免重复相同失败组合。不会据经文补写原文，也不把任意同音词强制改为人物名。

HY-MT 的简短恢复模板和术语提示格式参考[官方模型说明](https://huggingface.co/tencent/HY-MT1.5-1.8B)。保留本机 Qwen3-ASR 0.6B MLX INT8、HY-MT Q8_0 Metal、mac-verified 采样、Kokoro 中文整句合成及原生 PCM 播放/字幕时钟。未修改原生音频采集或合成速度算法。

## 验证边界

针对性测试覆盖异常输出恢复、重复失败、token 上限、正常翻译、实际讨论翻译规则的合法原文、双语分句、术语边界，以及已播内容的追加和去重。WebSocket 回归对旧版复现新增内容未发布，新版确认只为新增内容发布一次语音任务。

补读只针对可明确对齐的末尾新增。对已经朗读的句中改写、否定修正等，不自动重播，也不能宣称它们已经纠正到听众耳中。术语表不能消除 ASR 同音错误，输出保护也不能保证普通译文语义完全准确。

第一轮完整 Genesis 2/3/4 长测发现：术语列表与长提示词组合会交换亚伯/该隐的职业，或把以诺误当为母亲。20 次真实模型对照定位到提示组合问题；按原文顺序配合简短模板后，两项回归恢复正确，另复测了原异常输入和中文专名。完整记录在本机 artifacts/macos/translation-integrity-2026-09-14 中。
