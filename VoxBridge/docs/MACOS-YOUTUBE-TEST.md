# 油管译音测试环境 · 1.5.0（build 15）

> 名称说明：当前项目中文名称为“同声传译”。本文保留验证当时使用的应用名称与路径。

2026-09-14，在 M4 MacBook Air 24 GB / macOS 26.6.2 验证。

## 日常操作

1. 打开 `/Applications/教会同声传译.app`，桌面入口指向同一 App。
2. 输入选 **系统播放声音 · 只听译音**，朗读输出选 **系统默认输出**，方向选 **英文 → 中文**。这些设置会自动保存。
3. 在 macOS 选择希望收听译音的输出设备。使用耳机时先连接并将其设为系统默认输出；也可以在 App 中明确选择该耳机。
4. 点击 **开始传译**，等待显示“传译运行中”，再播放 Chrome 中的 YouTube。视频保持正常音量，不要点击网页静音。建议每次先播放 30–60 秒并关闭自动播放。
5. 停止测试时先暂停视频，再点 **结束传译**，App 完成最后一句并等待译音收尾。模型保持就绪，可以再次开始。停止服务会释放模型。

流程：Chrome 视频音频 → 原生 Core Audio tap → 本机 Qwen ASR → HY-MT → Kokoro 中文 → App 原生 PCM 播放 → macOS 默认输出。

“只听译音”会抑制所采集的其他应用原声，App 自己的 TTS 被排除并正常输出。无需 BlackHole、多输出设备、浏览器共享标签页或虚拟声卡；不修改系统音量、默认设备或全局静音设置。该输入采集其他应用的系统声音，测试时关闭其他正在播放音频的程序。监控网页可关闭，不参与音频采集、翻译和本机播放；不要另外打开本机听众朗读页重复播放译音。

系统音频录制权限由 macOS 管理；拒绝时 App 显示操作指引。等待权限时可以取消开始传译；晚到的系统调用在返回后自行释放采集资源，不会继续提交 PCM。

## 保留的本机配置

- Qwen3-ASR 0.6B MLX INT8；英文 → 中文固定 English ASR。
- HY-MT1.5-1.8B Q8_0，沿用已验证的方向提示词与设置。
- Kokoro 中文 v1.1、`zm_029` 男声、CPU 2 线程、基准 1.05 与 Auto 追赶。
- 1.4.3 中文整句切分、实际播放时钟驱动字幕、现有 PCM/HLS 播放调度。
- 服务仍使用端口 8024，局域网入口由 App 自动选择 IP。

本次不是更换识别/翻译/TTS 模型，也没有修改语音合成或播放排程代码。

## 实测与回归

真实 Chrome 测试使用 [Stanford 官方 Steve Jobs 演讲](https://www.youtube.com/watch?v=UF8uR6Z6KLc&t=60s)，从 1:11 播放到约 1:49 后暂停，自动播放关闭。没有下载音频或使用文件注入替代系统采集。

- 英文识别、中文翻译和 TTS 持续产生；用户听有线耳机后确认 **“只有中文译音”**。
- 暂停视频后，输入电平为 0，App 仍有 4.7 秒中文朗读缓冲；之后缓冲排空。未观察到译音重新形成系统输入。
- 本地监控保存 7 条翻译记录，无会话或 TTS 错误。片段末尾 ASR 仍产生了不准确的 “P. C.”，音频路由验收不代表识别准确率满分。
- 用户随后指定 **系统默认输出**，最终设置使用该选项。
- 新增回归先复现了等待权限 30 秒后的 WebSocket idle timeout，以及停止阻塞在同步 `AudioDeviceStart` 之后的问题。修复使用独立 JSON 保活任务与可取消的串行 HAL 资源管理。
- `NativeLifecycleChecks.swift` 在真实 8024 服务上等待 35 秒、期间不提交 PCM，连接保持；启动取消、设备丢失、并发停止和资源释放检查通过。
- `SystemAudioTapChecks.swift` 覆盖自身进程排除、条件静音、私有聚合设备、显式停止、仅取消启动 Task、晚到启动清理、正常停止清理和部分初始化失败；全部通过。
- `AudioCaptureChecks.swift` 的采样率转换、PCM 拷贝、缓冲上限和停止排空检查通过。
- Python 服务/PCM 路由回归：31 passed；一个既有 Starlette/AnyIO 弃用警告。
- 最终 App 重新编译、签名验证并安装到原路径。
- 最终安装的 App 使用“系统默认输出”，在视频暂停时开始传译并连续观察 35 秒，保持运行且没有会话/TTS 错误；随后实际播放约 30 秒（1:49–2:19），再次生成英文识别、中文译文和待播语音。暂停后输入电平回到 0，正常结束；同一 App 立即再次开始成功，再次停止后保持服务就绪。

本机原始状态证据保存在 `artifacts/macos/youtube-headphones-1.5.0/`。本指南使用已部署在此 Mac 的模型和环境；仅复制 `.app` 不会同时复制模型。
